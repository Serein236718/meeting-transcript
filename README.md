# meeting-transcript · 腾讯会议文字稿整理

![version](https://img.shields.io/badge/version-1.0.0-blue)
![license](https://img.shields.io/badge/license-MIT-green)
![python](https://img.shields.io/badge/python-3.8%2B-3776AB)
![skill](https://img.shields.io/badge/WorkBuddy-Skill-6f42c1)

**把腾讯会议某场会录音，整理成一份带发言人标注、带时间戳、能逐句核对的 `.txt` 文字稿。**

说一句「帮我整理一下昨天那场会」，它会先问日期、列出当天全部会议、把参会人摊开给你确认，
然后才动手取转写。三步确认，只为不选错那场会；取到转写后按发言人合并段落，原话一个字不改。

> **English summary**
> A WorkBuddy / Claude-style skill that turns a Tencent Meeting recording transcript into a
> speaker-labelled, timestamped plain-text (`.txt`) transcript. It enforces a three-step
> confirmation flow (meeting date → pick the session → verify participants) so you never
> transcribe the wrong meeting, and it keeps every utterance verbatim — no rewriting, no
> polishing, ASR errors are marked in `〔〕` rather than silently fixed.

## 为什么需要它

会议记录不是「生成一段总结」，而是一次需要可核对的还原。三个最容易翻车的地方，正是这个技能的三个设计约束。

| 坑 | 实际场景 | 技能的应对 |
|---|---|---|
| **同一天五六场会** | 主题全叫「XXX 的快速会议」，时间还挨得很近，只看标题选，差十分钟就整篇作废 | 强制三步确认，最后用**参会人**做校验，未确认前不取转写、不建文件 |
| **AI 摘要在冒充原话** | 纪要是模型加工过的概括，具体数字、某句话、口头承诺都可能被抹平 | 默认走**录制转写**；用户明确要纪要时才走 AI 纪要，并标注「AI 加工版，非原话」 |
| **转写稿读不下去** | 原始 ASR 是上百个碎片段落、中英混杂、没有标点层级 | `build_transcript.py` 拼句 + 按发言人合并连续段落，再按话题切章节 |

## 效果预览

输出是纯文本，不是 Markdown。下面是形态示例（人名与内容已脱敏）：

```text
============================================================
会议文字稿
============================================================

【会议主题】项目周会
【会议号】  3913761200
【会议时间】2026-10-28 22:28:59 — 23:28:59（GMT+8）
【录制时长】43 分 41 秒（有效转写 00:00–43:38）
【参会人】  张三（创建者+主持人）
            李四（普通成员）
【交流形式】两人一对一沟通，前半段设备调试，后半段讨论项目排期
【转写来源】腾讯会议「文字转写」录制文件（自动语音识别）

------------------------------------------------------------
阅读说明
------------------------------------------------------------
1. 全文按交流进程分为 6 个部分，每位发言人单独成段并标注姓名。
2. 时间戳为 [分:秒]，是相对录制起点的偏移（录制起点 22:28:59），不是钟表时间。
3. 正文保留双方原始口语表达，未改写、未润色语法，因此存在口语重复、
   断句不完整等情况，均属原话特征。
4. 自动转写存在个别识别误差，凡明显无法还原之处以〔〕标注，不作臆测改写。
5. 07:04–11:32 无转写内容：双方在调整设备。

============================================================
一、开场与设备调试（04:15–07:04）
============================================================

[04:15] 张三：Hi, can you hear me?

[04:21] 张三：〔喂喂，喂喂。〕（ASR 识别噪声）

[06:01] 李四：Do you hear me now?

[06:03] 张三：Yes. Ok. 我们开始吧。
```

完整排版规范（章节切分、折行缩进、空档标注、文末脉络速览、交付自检清单）见
[`references/output-format.md`](references/output-format.md)。

## 三步确认，一步都不许跳过

每一步都必须由你的下一条真实输入推进。不确定就停下来问：不猜、不默认、不代选。

**第 1 步 · 反问会议日期**

给「今天 / 昨天 / 前天 / 其他日期」四个选项让你点。你如果一开口就说了日期，
它跳过这步直接复述确认；只给月日不给年份则按当前年份推，日期明显不合理会回来问你。

**第 2 步 · 列出当天全部会议，你来挑时间段**

```bash
tmeet meeting list-ended \
  --start "2026-10-28T00:00:00+08:00" \
  --end   "2026-10-28T23:59:59+08:00" --compact
```

按接口顺序原样呈现，**一场都不隐藏**（包括没有录制的）。只有一场也照样问你，不替你选。

```text
找到 2026-10-28 的 5 场已结束会议：

1. 20:12–21:12（02:05）｜张三的快速会议｜会议号 902884801｜有文字转写
2. 20:19–21:19（00:10）｜张三的快速会议｜会议号 342695628｜有文字转写
3. 21:15–22:15（00:13）｜张三的快速会议｜会议号 371563661｜有文字转写
4. 21:19–22:19（00:50）｜张三的快速会议｜会议号 369689563｜有文字转写
5. 22:28–23:28（43:41）｜张三的个人会议室｜会议号 3913761200｜有文字转写

要整理哪一场？回复序号即可，也可以直接说时间段（例如「22 点半那场」）。
```

**第 3 步 · 摊开参会人，请你确认这场对不对**

```bash
tmeet report participants --meeting-id "<该场 meeting_id>" --compact
```

```text
请确认是这一场：

会议：张三的个人会议室（会议号 3913761200）
时间：2026-10-28 22:28:59 — 23:28:59
参会人（2 人）：
- 张三（创建者+主持人） 22:28 入会 — 23:12 离会
- 李四（普通成员） 22:33 入会 — 23:12 离会

确认后我就开始提取转写并整理成文字稿。
```

展示完必须**结束本轮回复**，等你下一条真实输入说「确认 / 是 / 对」才继续。
你说「换一场」就回到第 2 步重列，不在原列表里猜。

## 安装

### 前置依赖

- **Node.js**：用于安装腾讯会议 CLI `tmeet`
- **Python 3.8+**：`build_transcript.py` 只用标准库，无需 `pip install`
- **腾讯会议账号**：对应会议的录制需具备「文字转写」（或至少有云录制）

```bash
# 1. 拉取到技能目录（用户级：所有项目可用）
git clone https://github.com/Serein236718/meeting-transcript.git \
  ~/.workbuddy/skills/meeting-transcript

# 想只对当前项目生效，就放到：
#   <你的项目>/.workbuddy/skills/meeting-transcript

# 2. 安装腾讯会议 CLI
npm install -g @tencentcloud/tmeet@latest

# 3. 登录（该命令会阻塞等待浏览器授权，必须在终端前台执行，不要放后台）
tmeet auth login

# 4. 确认登录态
tmeet auth status
```

技能目录名必须是 `meeting-transcript`，与 `SKILL.md` 里的 `name` 字段保持一致。

## 使用

在对话里出现下面任一表达，技能会被触发：

| 类别 | 示例说法 |
|---|---|
| 名词触发 | 会议纪要、会议记录、文字稿、逐字稿、转写稿、速记 |
| 动作触发 | 「把 10 月 28 日那场会整理一下」「整理一下昨晚的会议」「把会议内容导出来」 |
| 直接给条件 | 给出会议日期 / 会议号 / 会议主题并要求整理内容 |

**两种形态会分流**：

- 要**逐字稿**（默认）→ 走录制转写，原话全记录
- 要**纪要 / 总结 / 要点 / 待办** → 走 `tmeet record smart-minutes`，并在交付时标注「AI 加工版，非原话」

**不该触发的情况**：只查会议时间 / 参会人 / 会议号（直接查会议即可）；安排、修改、取消会议（属于会议管理）。

对话示例：

```text
你：帮我把 10 月 28 日 22 点半那场会整理成文字稿
它：（列出当天全部会议）→（确认时间段）→（展示参会人）→ 等你确认 → 出 txt

你：整理一下昨天的会议纪要，标清楚谁说了什么
它：先问你要「逐字稿（原话全记录）」还是「要点纪要（浓缩版）」，再按选择执行
```

## 它到底做了什么

底层不依赖任何自建服务，全部走腾讯会议 CLI，脚本只负责把碎片段落拼回人话：

```text
tmeet meeting list-ended        ── 列出当天全部会议（含 record_file_id / 转写状态 / 权限）
        │
        ▼
tmeet report participants       ── 参会人姓名 + 角色 + 入离会时间（防选错的最后一道闸）
        │
        ▼
tmeet record transcript-get     ── 取转写 JSON（先过 state 与 permission 两道闸）
        │
        ▼
scripts/build_transcript.py     ── 拼句、按发言人合并、回报统计
        │
        ▼
YYYY-MM-DD HH-MM_主持人.txt     ── 纯文本交付，UTF-8 / LF
```

### build_transcript.py

```bash
# 段落输出到 stdout
python3 scripts/build_transcript.py transcript.json

# 写入文件
python3 scripts/build_transcript.py transcript.json --out blocks.txt

# 不折行（默认按 76 字符折行，续行缩进 7 格对齐正文）
python3 scripts/build_transcript.py transcript.json --width 0
```

它解决一个具体的坑：ASR 返回的是「段落 → 句子 → 词」三层嵌套，
**句子文本只藏在 `words[].text` 里，没有 `sentence.text`**。
脚本负责拼句、把同一发言人的连续段落合并，并在 stderr 打出统计供你核对是否取全：

```text
段落数 147（合并后 131 段）｜句子数 229｜张三 76段、李四 71段｜时间范围 04:15-43:38
```

这行统计是交付前的核对依据：正文段落数要和它对得上，时间戳要从首段连续到末段。

## 输出规范

| 项 | 规范 |
|---|---|
| 文件类型 | `.txt`，UTF-8（无 BOM），LF 换行，正文不得出现 Markdown 记号 |
| 文件名 | `YYYY-MM-DD HH-MM_主持人.txt`，例 `2026-10-28 22-28_张三.txt`（冒号在文件名里写作 `-`） |
| 主持人 | 取参会人里角色含「主持人」者 → 退用「创建者」→ 再退用第一位发言人 → 均无则「未标注主持人」 |
| 头部 | 会议主题、会议号、时间、录制时长、参会人、交流形式、转写来源 |
| 阅读说明 | 编号 4–5 条：时间戳含义、原话保留原则、误差标注方式、无转写空档 |
| 正文 | 分 6–8 个话题章节，`[mm:ss] 姓名：原话`，段间空一行，约 76 字符折行 |
| 分节线 | `=` 60 个用于章节标题，`-` 60 个用于小节与说明 |
| 原话原则 | 口语重复、语法错误、断句中断一律保留；ASR 明显误识别用 `〔〕` 标注，不猜测补写 |
| 文末 | 内容脉络速览（时间 + 一句话）+ 整理说明（来源、保留原则、误差标注方式） |

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| 命令报 `user config is empty` | 未登录，执行 `tmeet auth login`（前台跑，等浏览器授权） |
| 当天一场会议都没有 | 提示你换日期，**不会**自动去查邻近日 |
| 会议既无转写也无录制 | 该场无可取内容，建议换一场 |
| 只有「云录制」没有「文字转写」 | 用云录制的 `record_file_id` 试 `transcript-get`；不行则退到 AI 纪要并标注 |
| 录制状态是「录制中 / 转码中」 | 等转码完成再取，此时不发起权限申请 |
| 错误码 `500284` | 当前账号无该功能权限，如实告知，不重试、不推测原因 |
| 转写只有零星几句 | 如实告知实际覆盖区间，不用纪要内容冒充逐字稿 |

## 局限与说明

- **依赖腾讯会议**：需要有效账号、对应会议的录制与转写权限；权限不足时走申请流程，`closed` / `deleted` 则无法获取。
- **ASR 有误差**：识别错的字一律保留原样并用 `〔〕` 标注，不做推测性补写 —— 文字稿是记录，不是创作。
- **不做摘要**：本技能交付逐字稿；要点、待办、结论属于加工产物，需你明确要求才会走 AI 纪要分支。
- **隐私**：参会人信息只用于本次确认与文字稿标注，不外传、不写入任何第三方服务。
