# 文字稿输出格式规范

本文件是生成 `.txt` 文字稿时的排版依据。**生成前完整读一遍，照模板填。**

## 一、文件命名

```
YYYY-MM-DD HH-MM_主持人.txt
```

| 部分 | 取值 | 说明 |
|---|---|---|
| `YYYY-MM-DD` | 会议**开始**日期 | 取自 `start_time` / `schedule_start_time` |
| `HH-MM` | 会议**开始**时刻 | 冒号在文件名中写作 `-`（Windows 禁用冒号），如 22:28 → `22-28` |
| `主持人` | 主持人姓名 | 见下方取值优先级 |

主持人取值优先级：

1. `report participants` 返回的 `participants[].user_role` 含「主持人」者的 `user_name`
2. 无「主持人」标注时，取含「创建者」者的 `user_name`
3. 仍无 → 转写里出现的第一位发言人
4. 全部缺失 → `未标注主持人`

姓名做文件名净化：`/ \ : * ? " < > |` 替换为 `-`，去掉首尾空格。

示例：`2026-10-28 22-28_断桥烟雨.txt`

## 二、整体骨架

```
============================================================
会议文字稿
============================================================

【会议主题】<subject>
【会议号】  <meeting_code>
【会议时间】<YYYY-MM-DD HH:MM:SS> — <HH:MM:SS>（GMT+8）
【录制时长】<H 小时 M 分 S 秒 / MM 分 SS 秒>（有效转写 00:00–<mm:ss>）
【参会人】  <姓名>（<身份 / 单位 / 角色>）
            <姓名>（<身份 / 单位 / 角色>）
【交流形式】<一句话概括会议性质与议程>
【转写来源】腾讯会议「文字转写」录制文件（自动语音识别）

------------------------------------------------------------
阅读说明
------------------------------------------------------------
1. 全文按交流进程分为 N 个部分，每位发言人单独成段并标注姓名。
2. 时间戳为 [分:秒]，是相对录制起点的偏移（录制起点 <HH:MM:SS>），不是钟表时间。
3. 正文保留双方原始口语表达，未改写、未润色语法，因此存在口语重复、
   断句不完整等情况，均属原话特征。
4. 自动转写存在个别识别误差，凡明显无法还原之处以〔〕标注，不作臆测改写。
5. <如存在无转写空档，在此说明区间与原因；无则省略本条>
```

头部要点：

- 参会人一行一位，续行用空格对齐到【】之后
- 「交流形式」写实：一对一英语口语练习 / 项目周会 / 客户沟通，配一句议程概述
- 「有效转写」取首段 `start_time` 与末段 `end_time`，与录制总时长的差值在阅读说明里点到

## 三、章节与正文

### 章节标题

```
============================================================
一、开场与设备调试（04:15–07:04）
============================================================
```

- 用中文序号（一、二、三……），标题「概括话题 + 时间区间」
- 章节数量按会议实际内容定，常见的 6–8 个：
  开场试音 → 正式开场/自我介绍 → 主体讨论（可拆多节）→ 自由交流 → 收尾
- 主体讨论若是问答形式，在章节内再加小节标题：

```
------------------------------------------------------------
Q1｜<问题概括>
------------------------------------------------------------
```

### 发言段

```
[04:15] 断桥烟雨：Hi, can you hear me?

[06:01] Jakub：Do you hear me now?
```

- 格式固定：`[mm:ss] 姓名：正文`
- 段间空一行，段内不空行
- 正文超过约 76 字符时折行，续行缩进 7 个空格（对齐到「姓名：」之后）

```
[12:06] Jakub：Okay. I'm from Poland, but I am right now on study exchange in
       Portugal, So that's why we talk, I think, And I study management and
       tourism. On Polytechnic university is but important, I study tourism
       and recreation on. Physical Academy. Do you have some hobby or something
       like that?
```

- 同一发言人连贯的一段话合并为一段，不逐句断行；问答交替时逐轮分段
- 转写为空的时间空档单独标注，不退化成占位符：

```
       〔07:04–11:32 无转写内容：双方在调整设备与就座位置〕
```

## 四、原话保留与误差标注

| 情况 | 处理 |
|---|---|
| 口语重复（"I I think"） | 原样保留 |
| 语法错误、断句中断 | 原样保留，不修正 |
| 中英混说 | 原样保留（"豆包 is very good at chatting"） |
| 明显 ASR 错识别 | 保留原文，追加 `（ASR 识别噪声）` 或 `（应为 xxx，ASR 误识别）` |
| 完全无法还原的碎片 | 包在〔〕里，不猜测补写 |
| 说话人归属明显错位 | 不改归属，按 ASR 结果如实记录 |

标注示例：

```
[04:21] 断桥烟雨：〔湖南，湖南。〕（ASR 识别噪声）

[42:20] 断桥烟雨：〔You are a. 我是 gay right。〕（应为 "I'm in Greece,
       right"，ASR 误识别）
```

**禁止**：整句改写、把口语润色成书面语、把没听清的部分按上下文编出来。

## 五、文末

### 内容脉络速览

纯文本对齐，不用表格线：

```
============================================================
附：内容脉络速览
============================================================

04:15–07:04  开场试音，<一句话>
07:04–11:32  无转写（<原因>）
11:32–13:11  <内容概括>
...

```

- 时间列宽统一（如 12 字符），概述列左对齐
- 只写实际发生的事，不写评价、不写建议

### 整理说明

```
------------------------------------------------------------
说明：本文由腾讯会议文字转写自动生成后整理，仅做分段、标点与发言人
标注，未改动原话内容。自动识别误差以〔〕标出，未作推测性补写。
------------------------------------------------------------
```

## 六、交付前自检清单

- [ ] 文件是 `.txt`，UTF-8 编码，无 BOM
- [ ] 文件名符合 `YYYY-MM-DD HH-MM_主持人.txt`，无冒号等非法字符
- [ ] 正文无 Markdown 痕迹（`#`、`**`、`|`、`>`）
- [ ] 时间戳从首段连续到末段，无跳段、无重复段落
- [ ] 每位发言人都标了姓名，无「未知发言人」残留
- [ ] 空档区间已注明，未用占位文字填充
- [ ] 参会人姓名与 `report participants` 返回值一致
- [ ] `build_transcript.py` 报的段落数与正文段落数一致
